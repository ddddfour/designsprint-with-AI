# Components

Component specifications and documentation for the design system.

## Structure

One file per component, e.g.:
- `button.md`
- `card.md`
- `input.md`
- `navigation-bar.md`

## Component Documentation Format

Each component file should include:
1. **Purpose** — What the component is for
2. **Variants** — Different states and configurations
3. **Token Usage** — Which design tokens it references
4. **Accessibility** — Requirements (contrast, labels, touch targets)
5. **Prototype Reference** — Link to the implementation in the chosen prototype medium
6. **Production notes** — Corresponding component in the chosen production stack

## Creating Components

Components are defined during the Prototype phase as the UI takes shape. Use `/ui-design` to build them and document here.
